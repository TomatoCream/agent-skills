# GOTCHAS THAT BITE
#  * Put :PROPERTIES: immediately after the heading. `org-anki--entry-content-
#    until-any-heading' skips the heading, then skips the property drawer, so
#    any text written ABOVE the drawer is silently discarded from the payload.
#  * #+ANKI_TAGS: is colon-separated. Space-separated values become one tag.
#  * Fields absent from `org-anki-model-fields' are silently dropped, even if a
#    matching subheading exists (see the Add Reverse card in Part 1).
#  * Comment lines ("# ...") do not survive org export, so they cannot fill a
#    field; a card whose only body is comments is incomplete.
# ---------------------------------------------------------------------------
# BUFFER-WIDE SETTINGS (resolution tier 3; see `org-anki--find-prop')
# ---------------------------------------------------------------------------
# Only the FIRST matching keyword is used; a second #+ANKI_DECK: is ignored.
#+ANKI_DECK: showcase
#+ANKI_NOTE_TYPE: Basic
# MATCH passed to `org-map-entries' by `org-anki-sync-all'
# (`org-anki--get-match'): tagged :anki: AND not tagged :noexport:.
#+ANKI_MATCH: anki-noexport
# Buffer-wide tags (`org-anki--get-tags'). COLON-separated; a space-separated
# value becomes ONE tag containing spaces. "__" is rewritten to "::" when
# `org-anki-hierarchical-tags-separator' is set, and the rewrite covers these
# tags too -- so "showcase__mastery" reaches Anki as "showcase::mastery".

* Part 1: Core Card Types & Field Mapping

** Basic note: title is Front, body is Back :anki:
This body text becomes the Back field.

`org-anki--get-fields' finds no child headings matching the model fields, so it
takes the entry title as the first field and this content as the second
(the "no fields found in subheadings" branch). The entry has no
:ANKI_NOTE_ID:, so `org-anki--sync-notes' routes it to `addNote' and
`org-anki--handle-pair' writes the returned integer ID into this entry's
:PROPERTIES: drawer. Later syncs use `updateNoteFields' plus a tag diff
(`org-anki--tag-diff' -> addTags/removeTags).

*** Front :noexport:
In a concurrent kernel architecture, analyze this virtual memory page table
descriptor layout:

#+BEGIN_SRC c
/* 64-bit Virtual Memory Translation Descriptor */
struct PageTableEntry {
    uint64_t physical_frame : 40; /* 40-bit physical page frame address */
    uint16_t reserved       : 11; /* Architecture-reserved bits          */
    uint8_t  cache_disable  : 1;  /* Disable L1/L2 hardware caching      */
    uint8_t  write_through  : 1;  /* Write-through vs write-back policy  */
    uint8_t  user_accessible: 1;  /* Ring 0 kernel vs Ring 3 user mode   */
    uint8_t  read_write     : 1;  /* 0 = Read-only, 1 = Read/Write       */
    uint8_t  present        : 1;  /* Page residency flag                 */
};
#+END_SRC

*Analytical Questions:*
1. What happens at the hardware level when a thread executes a *write* to an
   address mapped by this entry if ~present == 1~ but ~read_write == 0~?
2. If page size is $P = 4\text{ KiB} = 2^{12}\text{ bytes}$, what is the
   maximum physical memory addressable by this descriptor?

\begin{equation}
\text{Max Physical Address} = 2^{(\text{frame bits} + \text{offset bits})}
\end{equation}

| Flag              | Value | Architectural State                         |
|-------------------+-------+---------------------------------------------|
| ~present~         |     1 | Page resident in physical DRAM              |
| ~read_write~      |     0 | Page protected as *read-only*               |
| ~user_accessible~ |     0 | Accessible only in supervisor mode (Ring 0) |

*** Back :noexport:
*1. Hardware & Kernel Exception Sequence:*
- The MMU checks page privileges during virtual-to-physical translation.
- On a store against a descriptor with ~read_write == 0~, the MMU raises a
  *#PF (Page Fault Exception)* (vector 14).
- The CPU pushes an error code:
  - bit 0 (~P~) = 1 (protection violation, not a missing page).
  - bit 1 (~W/R~) = 1 (the access was a write).
- The OS handler then terminates the process with ~SIGSEGV~, or resolves the
  fault through *Copy-On-Write (COW)*.

*2. Address Space Proof:*
40 frame bits plus $\log_2(4096) = 12$ offset bits:

\begin{align}
\text{Total Address Bits} &= 40 + 12 = 52\text{ bits} \\
\text{Max Addressable Space} &= 2^{52}\text{ bytes} = 4\text{ PiB}
\end{align}

*4. Comparison Summary:*
| Dimension          | ~present == 0~ (translation)     | ~read_write == 0~ (protection)         |
|--------------------+----------------------------------+----------------------------------------|
| *Exception*        | #PF (missing entry)              | #PF (permission violation)             |
| *Error code bit 0* | 0 (non-present page)             | 1 (protection check failed)            |
| *Resolution*       | demand paging from swap/storage  | COW fork replication or ~SIGSEGV~      |
| *Hardware cost*    | high ($> 10^5$ cycles / disk IO) | low ($\approx 10^2$ cycles if COW)     |

# Part 7: Command Reference (all verified present in org-anki.el)
#
#   org-anki-sync-entry    sync the single entry at point (add or update+tag diff).
#   org-anki-sync-all      org-map-entries over MATCH (#+ANKI_MATCH: else
